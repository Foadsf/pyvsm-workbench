### Root Cause & Fix
In PySide6 (Qt 6), the `QFont` constructor signature is:
```python
QFont(family: str, pointSize: int = -1, weight: int = -1, italic: bool = False)
```
Passing `QFont.StyleItalic` (a `QFont.Style` enum) as the 3rd positional argument caused `TypeError: 'QFont.__init__' called with wrong argument types: (str, int, Style)` during canvas paint events.

**What I'd change**
1. **Interactive stepping is the weak point.** Gemini plans to re-run `.tran` in short slices and carry state across them with `.ic`. That creates discontinuities and re-initialises the solver every slice. It is also slow when each slice launches an `ngspice -b` process. The proper route is `libngspice` with a background thread. You pause and resume it, change component values with `alter`, and use `GetVSRCData` for external sources. Make `libngspice` the primary interactive path and treat sliced CLI runs as a degraded fallback.
2. **The RC acceptance test is too loose.** A tolerance of ±50 mV on a 3.16 V value would hide a bad state carry-over. Tighten it to ±5 mV.
3. **The test fallback solver can mask problems.** Tests that pass on the fallback don't show that ngspice works. Once ngspice is installed, tests marked `ngspice` should fail rather than skip when it's missing, and the fallback should be used only in tests.
